    k8s cluster | my-app pod | my-app service | my-app ingres

    External request comes from browser will go to ingress -> 2) Ingress will transfer to service -> 3) Then service transfers to pod-> lastly pod

    Example Ingress file. it is of kind Ingress. it has routing rules. it has host name, forward request to the internal service.

    apiVersion: networking.k8s.io/v1 kind: Ingress metadata: name: my-sample-ingress spec: rules: - host: my-app.com #browser URL will go to my-service, forward request to internal service. http: #httml protocol. paths: # url path, ** after the domain in URL. backend: service: name: my-service port: number: 80

    Note : http in above is the same as what we see in url, so it is different from http://domain.com http in above refers to Incoming request gets forward to internal service. host should be a valid domain address, map domain Name to NODE IP address. In ingress, no NodePort in internal service. Default ClusterIP will be used.
