    Configurations- deployment&service

    -----------------------------k8s configuration----------------------------- Each configuration file has 3 parts 1. metadata 2. specification 3. status // Status will be automatically added by k8s.

    k8s has self healing mechanism, it validates desired spec with actual spec. If there is deviation between these two it self heals. Status of current would come from etcd of master node() i.e brain of cluster. cluster changes are stored in etcd (mentioned in 1.architecture.md )

    Connecting Deployment to pods pod name label has to match with matchLabels of deployment Connecting service to deployments service app name has to match with deployment app name & pod app name pod to service pod container port has to match with service targetPort.

    // connection has been established.
